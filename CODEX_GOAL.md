Performance architecture — essential requirement, not optional polish
Use event-driven incremental synchronization, not full recursive scans on every change:
- On initial connection enumerate each root once, build SQLite per-side entries (task_id, side, normalized relative path, type, size, nanosecond mtime where available, file ID when available, cached BLAKE3 content digest, index generation, last-seen status). Persist the last successfully synced per-relative-path baseline, two-sided status, tombstones/deletions, run journal, and dirty directories. Treat cached metadata as hints, not proof of identical bytes.
- Maintain a hierarchical cached directory digest / Merkle-style index constructed from child names/types/cached hashes. On a confirmed single-file change, update that file and only affected ancestors. Crucial: a cached directory hash alone cannot reveal arbitrary external changes; never imply it avoids a recovery scan if notifications were missed.
- Subscribe recursively using Windows ReadDirectoryChangesW through the notify backend or a direct windows-rs implementation if needed. Capture creates, writes/saves, deletes, renames, folder changes. Watch both sides, including SMB if the server supports notifications. Coalesce editor save bursts, delay until files stabilize/unlock, handle rename pairs, ignore our own verified writes without ignoring external changes, and enqueue the minimal dirty paths. One changed file should not trigger a full-tree walkdir scan or hash every sibling.
- On watcher overflow, invalidation, unmount/disconnect, process restart, or unsupported network notification, mark index uncertain and perform a controlled reconciliation. Prefer narrow scans for known dirty directories; do a complete metadata reconciliation when uncertainty spans the whole tree. Full scan also remains available by explicit user request and optionally infrequent safety schedule. Never claim offline SMB changes can be reconstructed purely from the local index. On SMB, keep Windows notification buffers within documented network constraints (notably max 64 KiB for ReadDirectoryChangesW).
- Local NTFS USN change journal is an optional, permission-aware optimization for catching missed changes. Implement it only if genuinely available without unreasonable privileges; it is not available via SMB. Fall back gracefully without prompting normal users for admin rights.
- On events, use SQLite to locate only affected records; stat and BLAKE3 hash changed files only when justified. Stream hashing/copying with bounded memory. Reuse cached hashes for unchanged files. Ensure correctness even for timestamp-preserving edits and metadata collisions through event invalidation, explicit verify mode, and recovery scan.
- Ensure durable queues/checkpoints, transactional baseline advancement only after successful operations, resumable/replay-safe execution, fairness, cancellation, limited parallelism and optional bandwidth caps. Instrument scanned_entries, hashed_bytes, watch_events, queued_paths, copied_bytes, reconciliations per run to prove incremental behavior.
- Build a benchmark for a large synthetic tree (at least 10,000 files, optionally 100,000 if resources permit), modify one file, and report actual wall time, number of enumerated entries, bytes hashed, peak memory, and comparison against forced full scan. Do not invent speedup factors. Pass condition: steady-state single-file event processing does not enumerate or rehash the complete tree.
