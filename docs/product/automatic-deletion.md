# Approved automatic deletion

This implements the unattended deletion requirement in CODEX_GOAL.md. It defaults off for every task. It is separate from enabling monitoring, schedules or login triggers.

The editor offers explicit opt-in for two-way and mirror tasks after a full manual Preview/Apply succeeds without unresolved conflicts. The separate confirmation names both roots and both limits. The backend independently enforces this prerequisite. Schema 3 stores the manual run ID, root identities, mode and scope in `baseline_reviews`, transactionally with the terminal successful run. Automatic runs cannot create this approval. Existing installations need a fresh successful manual reconciliation; old run history alone does not grant approval. Scope changes require saving with deletion off, manually reconciling, then opting in again. Import and duplication disable the policy.

Each queued plan counts proposed removals, including directories and descendants. Every surviving object must still match a non-null common baseline digest. Both limits must pass: maximum entry count (default 20) and maximum percentage of indexed, non-tombstoned common-baseline entries (default 10%). The denominator includes only baseline paths still represented in the scoped per-side index. It is an index-derived population, not a fresh whole-tree scan. Exact equality passes; integer multiplication avoids rounding. Limits apply per run, not across a rolling time window. Repeated small deletions can therefore exceed a limit cumulatively; the editor states this explicitly.

Mirror destination extras without baseline evidence remain manual. Move always remains manual. Missing roots, changed identities, partial enumeration, stale inputs and changed survivors retain existing failure/conflict protections. Deletion rechecks the opposite side is absent before protection and again immediately before file disposition; reappearance during a protected copy stops the run with both files intact. These checks cannot make two independent roots atomically consistent against a writer racing after the final check; the survivor recovery copy remains available. An empty result after successful enumeration is not automatically trusted for a large deletion: the percentage and entry limits still apply. User-selected 100% permits the whole indexed population only within the entry limit; the explicit confirmation shows this value.

Automatic authorization uses the existing verified protected-removal executor. It does not bypass preflight, immediate source/destination checks, recovery copying or atomic Windows deletion safeguards. Conflicts stay preserved while independent permitted operations run. A blocked destructive plan waits for exact-plan manual review, including any other operations in that plan.

Runs store a structured decision: reason, removal count, indexed baseline count, configured limits and approving manual run ID. Run details display that decision in English/German; basic logs retain these IDs/counts without paths. Approval records are removed with task configuration; protected versions retain existing recovery behavior.

Verification: actual native both-root delete events, protected versions, edit/delete conflict preservation, unrelated copies, exact percentage boundary, whole-tree loss, entry limit, directory descendant counting, unavailable root, restart, scope changes, import disabled and automatic-vs-manual approval separation. The UI unit test proves policy enabling does not save before its separate confirmation. Installed end-to-end opt-in/debounce/deletion/review verification follows packaging.
